アンチグラビティ

A neo-cyberpunk stylesheet for websites, dashboards and small tools. One file, no framework, no build step. Link it, add one class, and plain HTML picks up the look; the .ag-* classes on this page add the rest.

Every example below is live. Its label is the class that draws it; open Code under any example for markup you can copy. The theme and highlight controls in the bar restyle the whole page.

00 Getting started

Five minutes from a blank page to a working layout.

01

Link the stylesheet

Add this to the <head> of every page. The /v2/ file updates in place with fixes and new elements, and never with changes that break your markup.

<link rel="stylesheet" href="https://style.rogues.nexus/v2/anti-gravity.css">
02

Set the theme, the highlight and the body class

data-theme and data-accent go on <html>; class="ag" goes on <body> and switches the styles on.

<!doctype html>
<html lang="en" data-theme="dark" data-accent="signal">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Example Site</title>
  <link rel="stylesheet" href="https://style.rogues.nexus/v2/anti-gravity.css">
</head>
<body class="ag">
  <header class="ag-shell">
    <a class="ag-display" href="/">Example</a>
    <nav aria-label="Main">
      <ul class="ag-linkline">
        <li><a href="/" aria-current="page">Home</a></li>
        <li><a href="/projects/">Projects</a></li>
      </ul>
    </nav>
  </header>
  <main class="ag-shell">
    <article class="ag-prose">…</article>
  </main>
</body>
</html>

03

Write plain HTML, then add components

Headings, paragraphs, links, lists, quotes, tables, forms, details, dialog, progress and meter are styled with no classes. Wrap long text in .ag-prose, lay pages out with .ag-shell, .ag-grid, .ag-stack and .ag-row, and reach for the components below when you need them.

One rule to remember: a plain <button> or <code> is only styled automatically when it has no class. If you give one a class for scripting, add .ag-btn to the button as well.

04

Mark state for people and screen readers

The stylesheet draws state from accessibility attributes, so the look and what assistive tech announces always agree.

AttributeUse it onEffect
aria-current="page"Nav, link line, menu and pager linksHighlights the current page.
aria-pressedToggles, filter menus, button groupsFills the active item with the highlight.
aria-selectedTabsUnderlines the selected tab.
aria-disabled="true"Pager linksDims a step you can't take.
aria-labelIcon-only buttons, each <nav>Names things that have no visible text.
aria-hidden="true"Hazard tape, barcodes, metersHides decoration from screen readers.
05

Optional: a custom highlight, self-hosted fonts and a load check

A custom highlight needs three shades. The colour picker in the Colour section works them out for any colour you choose.

:root {
  --ag-accent-dark:  #7CFF4F;  /* on Void */
  --ag-accent-light: #4EA132;  /* on Bone: fills and large text, 3:1 or more */
  --ag-accent-deep:  #3E7F27;  /* small text on Bone, 4.5:1 or more */
}

Fonts load from Google Fonts through an @import at the top of the stylesheet. To keep visitors off Google, serve Michroma, Chakra Petch, Share Tech Mono, Audiowide and Noto Sans JP (900) yourself and remove that line in your own copy.

The stylesheet ends with a marker, so a page can tell whether the whole file arrived:

if (!getComputedStyle(document.documentElement).getPropertyValue('--ag-loaded').trim()) {
  console.warn('anti-gravity.css did not load completely');
}

02 Type

Wide display type for headings and key data, Chakra Petch for reading, mono for codes and labels.

Headings need no classes. Use .ag-value for readouts, with the unit in .ag-unit, and .ag-label for the small grey text above them. Never set a headline that runs to two lines in the wide face; use h4. Taglines (.ag-slogan) are lowercase and end with a full stop. Use one katakana word (.ag-kana) per screen.

05 Buttons, tags & toggles

Square edges, wide caps. Anything at rest in light mode sits in void with bone text; active takes the highlight.

.ag-btn · --accent · --primary · --danger · --ghost · --slant · :disabled · .is-loading

One --primary per view. Labels are verbs, one to three words. --slant needs its label in a child <span>; .is-loading shows a busy state.

--sm · --lg · --icon · .ag-btn-group

Sizes and shapes. Give every --icon button an aria-label. .ag-btn-group joins toggle buttons that use aria-pressed.

button (no class) · input[type=submit|reset]

Unclassed buttons and submit or reset inputs get the default look automatically.

.ag-tag · --outline · --text · --slant · .ag-tone-*

Filled in the highlight by default. A .ag-tone-* class makes it a status tag and adds its glyph automatically (✓ ! ✕ i). --outline, --text and --slant change the weight; --slant needs a child <span>.

06 Forms

Plain form elements are styled with no classes. The .ag-* versions do the same job when you need classes on them.

.ag-field · .ag-input-group · .ag-field__hint · .ag-field__error

Put each control in an .ag-field with a <label>, and add a hint or an error under it (link an error to its input with aria-describedby). .ag-input-group adds a prefix or suffix. Unclassed inputs, selects and textareas are styled automatically; .ag-input, .ag-select and .ag-textarea do the same when you need classes.

What is Anti-Gravity?

A stylesheet with a neo-cyberpunk look. No framework and no build step.

Does it need JavaScript?

No. Tabs, toasts and the theme switch on this page use a little script, but every style works without it.

Can I change the colours?

Set data-accent on the html element, or set your own with --ag-accent-dark, --ag-accent-light and --ag-accent-deep.
